Hang-bag CRSI 阶段汇报

纯 π0.5 基线与 CRSI store_v5 的对比，以及方案是怎样一步步迭代到 v5 的。

01结论

虚线词可点开查看解释。

  1. 底层 VLA 决定上限。未微调的 pi05_base 0/10；LoRA 微调后，公共 seed 上 5/10。
  2. store_v5 追平基线。同样 10 个 seed，store_v5 5/10，LoRA 基线 5/10。逐 seed 看，v5 多成功 seed 43，少成功 seed 741192977。
  3. 每一步改进都来自上一版的失败。
    • π0.5 听不懂训练标签以外的指令，所以加了代码松爪；
    • 松爪的时机不对，所以改为由代码判断包的位置，并加了 lift_bag。
    v5 中，左臂阶段由框架造成的失败为 0。
  4. 瓶颈转到了右臂。v5 的 5 局失败全在右臂一侧：抓空、夹住后不提起、没挂上、太慢、不启动。
  5. 记忆还没起作用。v5 只形成了 1 条规则（包在原位时选 lift_bag），第 8 局后才出现，之后没有机会用上。

02设定

  • 任务：左臂把包放到桌子中间，右臂把包挂到钩上。仿真器判定 bag_hung 即为成功。每局上限 1900 步，20 Hz。
  • π0.5 指令：只用训练标签原文。左臂 pick up bag and place in middle，右臂 pick up bag and put on hook。
  • seed：LoRA 基线跑 20 个；pi05_base 和 store_v5 跑其中 10 个公共 seed，store_v5 从空记忆开始。
  • 随机性：同一 seed 加上同样的决策序列，轨迹完全相同。每组约 10 局，相差 1–2 局属于噪声。

04store_v5 的 RSI 工作机制

两条臂各是一个 agent。决策由 Qwen3-VL-8B 做；动作由 π0.5 执行，指令始终用训练原文；判断包的位置、执行代码动作由代码负责。agent 在下面四个时刻做决策：

时刻谁来决策可以选什么依据
1. 选子任务本臂空闲时Qwen 左臂：放包 place_bag_in_middle / 放后收回 retreat_after_place / 原地保持 hold_pose
右臂：挂包 hang_bag_on_hook / 原地保持 hold_pose		图像、本臂状态、对方消息、记忆。右臂必须先自己确认左臂已经放好，才能开始挂包。
2. 检查是否完成子任务运行 192 步后，每 64 步一次Qwen 看图 + 代码算数值通过 / 不通过由 Qwen 回答"包在桌上吗"这类看图问题，代码判断夹爪开合等数值，全部为"是"才算通过。
3. 中途决策连续 4 次检查不过，并且手臂不动Qwencontinue / pause / 代码动作，代码动作按包的位置提供（见下表）代码给出包的位置和左臂下一步该做什么，再加上记忆。
4. 更新记忆每局结束代码 + Qwen improver追加一条轨迹记录，重写规则代码算出的关键步数，以及每次中途决策之后有没有进展。

中途决策：按包的位置提供选项

代码对全局图像做颜色分割，和操作开始那一帧比较包的位移；"举在中间"和"放在中间桌面"由左臂末端高度区分。只用 agent 自己看得到的观测。

包的位置左夹爪左臂下一步提供给 agent 的选项
原位张开接近并夹住continue / pause
原位闭合提起continue / pause / lift_bag
离开原位，未到中间闭合搬向中间continue / pause
在中间，还举着闭合放低continue / pause
在中间，已在桌面闭合松爪continue / pause / release_gripper
在中间张开后撤无，操作完成

两个代码动作

  • lift_bag：夹爪保持闭合，末端竖直抬高 0.10 m（每步最多 0.02 m，最多 32 步）。之后交还 π0.5 继续执行原指令。每个操作最多做 2 次。
  • release_gripper：关节不动，把夹爪张开 16 步，再交还 π0.5。
  • 右臂没有代码动作，中途决策只能选 continue 或 pause。

记忆：在线滚动的轨迹记忆

  1. 记录：每局结束后，代码追加一条事实记录，包括关键步数，以及每次中途决策之后有没有进展；再附上 Qwen 写的一两句简述。
  2. 规则：Qwen 读全部记录，重写整套规则。
  3. 核实：程序逐条核实规则，至少 2 局支持、并且反驳少于支持，才保留。
  4. 使用：下一局的规划器和中途决策都读"规则 + 全部记录"。

目前的问题：

  • 规则的"支持"只看选项之后有没有进展，失败局也会被算作支持；
  • 第 9、10 局记录太长，超过 token 上限，没有更新；
  • 包被手臂挡住时，代码会误报"包已提起"。

07改进方向

针对 v5 剩下的右臂失败：

  • 右臂抓空后空手去挂（L，seed 5）：右臂夹爪闭合后，看包的像素是否跟着手移动来判断有没有抓空；抓空就张开重抓。
  • 右臂夹住后不提起包（K，seed 26）：把 lift_bag 扩展到右臂的挂包操作。在包已在中间、右夹爪闭合、手不动时提供。
  • 左臂撤回时拖走包，右臂没启动（J，seed 741192977）：release_gripper 之后，先由代码把张开的手竖直抬起，再交还 π0.5，避免手勾住提手。
